# deploy/remote-ssh/

## 架构概述
Remote SSH 发布脚本目录，用于把仓库同步到已安装 Docker 和 `docker-compose` 的远程服务器，并在远端运行专用 Compose 栈。

## 文件清单

| File | Pos | Function |
|------|-----|----------|
| deploy.sh | Remote SSH 发布入口 | 检查本地 SSH/rsync、`deploy/clash/config.yaml`、远端 docker-compose 与 `/dev/net/tun`，rsync 同步源码和配置，在远端执行 Compose `build --no-cache`、`up -d --force-recreate`、验证、日志、清理和上一版镜像回滚；默认创建远端 `backend/data`、`file-storage`、`agent-workspace`；向 nginx setup 传递前后端 host 端口；默认验证前端根路径；默认传递 Claude Code Docker nested sandbox 开关；默认生产 OAuth/CORS/cookie 配置匹配双域名 |
| docker-compose.yml | 远端 Compose 模板 | 复用 backend/frontend Dockerfile；默认资源规格对齐 Cloud Run，`tun-proxy` 发布后端本机端口并承载 Mihomo TUN，backend 共享 proxy 网络命名空间，前端暴露 HTTP；显式设置后端容器内部 `PORT`，避免与 host 映射端口脱节；文件存储和 Agent 工作区使用远端服务器文件系统；backend 使用 `SYS_ADMIN` + `seccomp=unconfined` + `apparmor=unconfined` 兼容 Claude Code / bubblewrap Bash sandbox；向前端根路径构建与后端 SEO 生成器传递 `REMOTE_FRONTEND_PUBLIC_ORIGIN` / `REMOTE_BACKEND_PUBLIC_ORIGIN` 派生的公开 URL，并覆盖本地 `.env` 中的 OAuth URL/cookie/CORS |
| setup-nginx.sh | Host 级 nginx 安装脚本 | 通过 SSH/SCP 在远端服务器安装 nginx、部署按 `REMOTE_BACKEND_PORT` / `REMOTE_FRONTEND_PORT` 渲染后的 `nginx/ink-and-memory.conf` 与 `nginx/suoxya-root.conf`（apex 站点）虚拟主机配置、启用站点；SSH 端口传给 `ssh -p` 与 `scp -P`；安装/启动前检查主机 `80` 端口，非 nginx 占用时中止，已有 nginx 占用时刷新配置并 reload；自动备份并禁用同域名旧 nginx 配置；支持 `WITH_SSL=1` 自动为 `suoxya.com` 及双子域名申请 Let's Encrypt 证书；使用前须设置 `REMOTE_SSH_HOST` |
| setup-storage.sh | 远端文件系统初始化脚本 | 创建或修复 `${REMOTE_APP_DIR}/backend/data`、`file-storage`、`agent-workspace`、`backups`，可通过 `REMOTE_STORAGE_OWNER`、`REMOTE_STORAGE_GROUP`、`REMOTE_STORAGE_MODE` 调整权限 |
| setup-swap.sh | 远端 swap 初始化脚本 | 幂等确保远端至少存在 `REMOTE_SWAP_SIZE_MB`（默认 2048MB）swap：不够时创建/启用 `REMOTE_SWAP_FILE`（默认 `/swapfile`）并写入 `/etc/fstab` 持久化；需要 root 或免密码 sudo，无权限时仅警告跳过而不中断部署；用于避免前端 `vite build`（mermaid/tiptap/ai sdk 依赖图需要 ~1G Node 堆）在 1G 内存主机上被 OOM Killer 杀死 |
| sync-data.sh | 远端数据同步脚本 | 只暴露 `backup`、`upload`、`download` 三个动作；`upload` 先备份远端数据、再上传本地 `backend/data`，并执行 Compose `up -d --force-recreate` 让后端重新加载数据库；`download` 先备份本地数据再下载远端目录 |
| nginx/ink-and-memory.conf | Host 级 nginx 反向代理配置 | 默认按域名路由：`ink-backend.suoxya.com` → `127.0.0.1:8765`，`ink-frontend.suoxya.com` → `127.0.0.1:8080`；前端域名根级 robots/sitemap/llms 直连后端生成器；由 `setup-nginx.sh` 在部署时按 Remote SSH 端口环境变量渲染；含 WebSocket 升级、SSE 长连接、SSL 模板 |
| nginx/suoxya-root.conf | Apex 域名 nginx 反向代理配置 | 主域名 `suoxya.com` 复用前端子域名背后的真实服务：`location /` → `127.0.0.1:8080`（frontend 容器），根级 robots/sitemap/llms 直连后端；复用 `ink-and-memory.conf` 中的 `map` 与 `upstream`（不重复定义）；由 `setup-nginx.sh` 同样按端口环境变量渲染并启用 |
