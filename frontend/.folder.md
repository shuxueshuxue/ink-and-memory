# frontend/

## 架构概述
React 19 + Vite + TypeScript SPA，部署在前端 origin 根路径 `/`，容器启动时生成 runtime-config 以支持跨域后端请求。

## 文件清单

| File | Pos | Function |
|------|-----|----------|
| Dockerfile | 容器构建 | 多阶段构建：Node 22 编译 → nginx 1.27 根路径服务静态文件；npm registry、`VITE_PUBLIC_SITE_URL`、构建期 Node 堆上限 `NODE_BUILD_MAX_OLD_SPACE_MB`（默认 512，Vite 8 rolldown 实测峰值 RSS ~605MB）通过 build arg 配置；用 `npm ci`（committed lockfile）+ `npm run build:docker`（跳过 `tsc -b`，仅 `vite build`）减少内存开销；1G 内存主机可直接完成构建，`deploy/remote-ssh/setup-swap.sh` 的 swap 仍作为兜底保留 |
| nginx.conf.template | 静态服务/兼容代理模板 | 从 `/` 服务静态 SPA；对 SPA HTML 与 `runtime-config.js` 禁用缓存；保留 `${BACKEND_URL}` 反向代理作为同源 fallback；代理 `/auth/`、`/oauth/google/`、`/oauth/device/code`、`/oauth/token` 到后端，同时保留 `/oauth/device/verify` 给 SPA；根级 SEO 文件代理到后端生成器；Docker Compose 中通过 `127.0.0.11` resolver 解析 `ink-backend` |
| docker-entrypoint.sh | 容器入口 | 渲染 nginx fallback 配置和 `/runtime-config.js`，注入 `API_BASE_URL` / `WS_BASE_URL` |
| .dockerignore | 构建优化 | 排除 node_modules、dist、.env 等 |
| package.json | 依赖管理 | npm 依赖声明；Vite 8（rolldown/Rust 内核）+ `@vitejs/plugin-react` v6；`npm run build`（`tsc -b && vite build`，本地/CI 全量类型检查）输出到 `dist/`；`npm run build:docker`（仅 `vite build`）供内存受限的镜像构建阶段使用 |
| vite.config.ts | 构建配置 | base `/`，dev proxy `/api` / `/auth` / `/oauth` / `/polycli` 到 localhost:8765；`/oauth/device/verify` 的 HTML 导航保留给 SPA；在 HTML 构建期替换 SEO public URL / image placeholders；低内存生产构建配置：关闭 sourcemap 与 gzip 体积报告，`manualChunks` 拆分 react/tiptap/markdown/ai-sdk 静态 vendor chunk，mermaid 及其 d3/dagre/katex 依赖图保持动态懒加载不进入静态 chunk |
| index.html | HTML 入口 | SPA HTML shell；包含 Codex SEO metadata、Open Graph/Twitter tags、JSON-LD WebApplication schema 和仅 `noscript` 展示的非 JS product overview，避免 React 启动前闪出 SEO 文本 |
| src/ | 应用源码 | React 组件、路由、API 调用 |
| public/ | 公共资源 | 字体/图片，以及 runtime-config 模板与默认配置 |

- 2026-07-20: Fixed frontend Docker image build OOM on 1G remote build hosts — `Dockerfile` now copies `package-lock.json` and runs `npm ci`, caps the builder stage heap via `NODE_OPTIONS=--max-old-space-size=${NODE_BUILD_MAX_OLD_SPACE_MB}` (default 1024, the measured minimum that lets `vite build` finish for this mermaid/tiptap/ai-sdk dependency graph — 448 and 768 both OOM), and runs the new `build:docker` script (`vite build` only, no `tsc -b`) since CI (`ci-frontend.yml`, `deploy-frontend.yml`) already runs the full type-checked `npm run build` on ample-memory GitHub runners. A ~1G heap alone still saturates a 1G-RAM host with no headroom, so `deploy/remote-ssh/deploy.sh deploy` now also provisions swap via the new `deploy/remote-ssh/setup-swap.sh` before building.
- 2026-07-20: Upgraded the bundler from Vite 7 (Rollup) to Vite 8 (rolldown/Rust) plus `@vitejs/plugin-react` v6 after measuring that Rollup's in-JS module graph (not file-read concurrency — `maxParallelFileOps` 5 still OOM'd at 768MB) drove the ~1.25GB peak RSS. Vite 8 builds the same graph at ~605MB peak RSS with a 512MB heap (`/usr/bin/time -l`, local arm64) and finishes `vite build` in ~0.5-0.9s vs ~5.3s. `Dockerfile` default `NODE_BUILD_MAX_OLD_SPACE_MB` drops 1024 → 512, so 1G-RAM hosts build without swap thrashing (swap provisioning stays as a safety net). `vite.config.ts` adds a low-memory build profile: `sourcemap: false`, `reportCompressedSize: false`, and `manualChunks` splitting react/tiptap/markdown/ai-sdk static vendor chunks while explicitly keeping mermaid, d3, dagre, and katex out of static chunks so `MermaidBlock` remains lazily loaded. Validated with `npm run build` (tsc + vite, exit 0), a 512MB-heap build, and a dev-server smoke test (HTTP 200, correct `<title>`).
