# Agent-Browser 通用 E2E 测试手册

本手册给出一个通用、可复用的 E2E 验收模板，重点关注 `agent-browser` 的流程与注意事项，不依赖具体业务系统。

## 1. 目标

- 用最小成本复现用户路径，并稳定产出可复核证据。
- 优先使用程序化执行（`agent-browser` + API）而非纯手工点击。
- 每次验证必须输出可比对工件：步骤日志、接口快照、截图、异常结论。

## 2. 术语约定

- `入口`：测试起点（通常是本地服务 URL 或已知登录入口）。
- `目标动作`：用户交互中关键分支（创建、提交、鉴权、提交、刷新、提交后状态校验）。
- `Smoke`：核心流程最小成功路径验证，不替代完整回归。
- `Snapshot`：页面/状态快照（截图、DOM、URL、network、console 等）。
- `阻塞`：外部依赖导致流程无法继续，不等于前端失败，应明确定义边界。

## 3. 先决条件

- 确认后端/前端服务已启动，端口明确（如 `127.0.0.1:<port>`）。
- 清理或隔离历史会话（避免脏状态污染）。
- 准备可复用 `agent-browser` Session 名称（例如 `/tmp/e2e-session`）。
- 外部依赖（如第三方 OAuth）可在测试环境预置，若不可预置需提前标注为阻塞。

## 4. agent-browser 标准启动方式

```bash
agent-browser \
  --session <your-session-path> \
  --headed
```

### 常用附加参数建议

- 本地路径固定 `--session`：保持 token/cookie 的持续性，减少“每次都重登”噪音。
- 需要扩展时按项目逐步加入，不要一次性叠加过多扩展。
- 多场景并发时请使用独立 `--session`，避免会话串扰。

## 5. 推荐执行序列（通用）

1. **启动会话与健康检查**
   - 打开目标首页，确认非空白、无明显加载报错。
   - 查看控制台关键日志是否出现热更新/编译成功信息。
2. **关键路径一：入口可达**
   - 进入主流程入口，确认可点击/可输入控件存在。
3. **关键路径二：核心动作链**
   - 按用户路径依次执行：表单填写 -> 提交 -> 结果返回。
   - 每一步记录 URL、返回体、可见组件状态变化。
4. **关键路径三：鉴权/第三方跳转（有则执行）**
   - 打开外部认证页时保留窗口/截图。
   - 观察跳回/返回成功条件是否满足。
5. **关键路径四：状态闭环**
   - 从前端状态回到服务端状态或数据层状态，确认一致性。
6. **关键路径五：回退与幂等验证**
   - 刷新/返回/重新进入，再次执行关键动作，确认结果可重复。
7. **证据归档**
   - 统一归档截图、接口响应摘要、控制台错误、异常判定和阻塞项。

## 6. 每步必须采集的证据

- 访问 URL 与最终 URL
- 关键页面截图（每个阶段至少一张）
- 网络请求摘要（至少主动作的 request/response）
- 异常日志（console/network/前端控制台）
- 会话关键字段（如 token、会话 id、对象 id）
- 结果判定（PASS/FAIL/BLOCKED）

## 7. 常见问题与处理

- **页面直接白屏或停在旧页**
  - 优先检查 `--session` 与启动参数；
  - 检查是否误用会话恢复状态导致历史页加载。
- **页面可见但控件无响应**
  - 检查是否有遮罩层、滚动容器遮挡、`z-index` 或高度约束。
  - 切换窗口尺寸验证响应式差异。
- **外部认证无法完成**
  - 标记为环境阻塞；记录外部依赖、使用到的账号/工作区状态。
  - 不将其判为业务功能回归失败。
- **请求成功但结果字段缺失**
  - 核对请求体契约与后端返回字段；补充回归断言，不要用本地替代掩盖。
- **无法稳定复现**
  - 固定 session、固定 viewport、固定时间点顺序，避免并发执行；保留重试前后日志。

## 8. 阻塞分类（必须写明解除 owner）

- `环境阻塞`：第三方依赖、测试账号、网络、会话状态。
- `数据阻塞`：后端数据不一致、已知环境脏数据。
- `实现阻塞`：产品功能本身失败或接口契约偏差。

每个阻塞都需要：`现象 -> 影响范围 -> 解除动作 -> 责任人`。

## 9. 结论输出模板（每次 run 必须给出）

- E2E 目标：`__`  
- 成功率：`PASS / FAIL / BLOCKED`  
- 已完成阶段：`1,2,3...`  
- 关键失败点：`__`  
- 证据路径：`截图/日志/API 片段`  
- 阻塞项与 owner：`__`  
- 是否可进入下一阶段：`Yes / No`
